# Data directory and restricted-data policy

## Core rule

This repository does not redistribute raw police microdata or any file containing protected, confidential or personally identifying information.

The repository may contain only code, documentation, configuration files, synthetic examples and non-identifying aggregate outputs whose public release is institutionally permitted.

## Source data used in the study

- MUNIC 2023 institutional indicators;
- SEGUP/CODEC police records covering 2022–2025;
- 2022 Census female population;
- IBGE municipal geographic data;
- municipal service-location information.

The 2022 female population is used as a fixed denominator for all annual police-record rates from 2022 through 2025.

## Directory policy

```text
data/
├── raw/         # Restricted or local source files; never commit
├── external/    # Locally obtained external files; never commit unless redistributable
├── processed/   # Derived files; publish only approved non-identifying aggregates
├── synthetic/   # Optional synthetic data for pipeline tests
└── README.md
```

The following paths are excluded by `.gitignore`:

- `data/raw/`;
- `data/external/`;
- `private/`;
- `secrets/`.

## Police microdata

Raw police records supplied by SEGUP/CODEC must remain outside version control. Researchers seeking to reproduce the full analysis must obtain authorization and source files directly from the relevant data provider.

Do not commit:

- row-level occurrences;
- names, identifiers or contact information;
- addresses or precise incident coordinates;
- free-text narratives;
- protected operational fields;
- credentials, tokens or restricted links;
- temporary exports that contain microdata.

## Allowed repository materials

Subject to provider and institutional rules, the repository may include:

- variable dictionaries;
- analytical category mappings;
- municipal name crosswalks;
- model configurations;
- code;
- aggregate exclusion logs;
- data-completeness summaries;
- municipal-level aggregate rates and final results;
- synthetic test data.

## Processed municipal outputs

Before publishing any file in `data/processed/`, verify that it:

1. contains no direct or indirect personal identifier;
2. is aggregated at the municipal level or another approved level;
3. complies with the provider's release conditions;
4. does not expose restricted free-text or operational fields;
5. has a documented schema and provenance;
6. is necessary for reproducibility.

## Zero completion rule

A missing municipality-category-year combination may be transformed into zero only after the corresponding annual extraction has been confirmed as complete. The processed dataset should preserve an annual completeness flag so that incomplete extraction is not confused with zero recorded events.

## Castelo dos Sonhos

Records associated with Castelo dos Sonhos are aggregated to Altamira for the municipal analysis because Castelo dos Sonhos is not an independent municipality in the 144-municipality analytical frame. The exact source-name crosswalk must be preserved in the preprocessing documentation.

## Synthetic data

Synthetic data may be added to test software execution, schemas and expected output dimensions. Synthetic files must be clearly labelled and must not be generated by lightly perturbing protected records in a way that could permit re-identification.
