# ELECTRE TRI-B complementary assessment

## Role in the study

ELECTRE TRI-B is used as a complementary multicriteria assessment and as part of the methodological triangulation. It is not external validation because no confirmed municipal ground truth of underreporting was available. The ELECTRE criteria are derived from related municipal data and are not statistically independent evidence sources.

## Criteria

All criteria are transformed into empirical percentile ranks in which higher values indicate greater investigation priority:

1. institutional fragility percentile;
2. low reporting visibility percentile;
3. territorial barrier percentile.

Temporal persistence is retained in the 216-scenario analysis and is not included as a separate ELECTRE criterion, avoiding direct double counting.

## Classes

The ordered classes are:

| Numeric class | Label |
|---:|---|
| 0 | Low |
| 1 | Moderate |
| 2 | High |
| 3 | Very high |

## Factorial sensitivity design

The 108 configurations are generated by:

```text
4 weight schemes × 3 profile schemes × 3 threshold schemes × 3 lambda values = 108
```

## Weight schemes

Criteria are ordered as institutional fragility, low reporting visibility and territorial barrier.

| Scheme | Weights |
|---|---|
| equal | 0.3333333333, 0.3333333333, 0.3333333334 |
| institutional emphasis | 0.45, 0.30, 0.25 |
| visibility emphasis | 0.30, 0.45, 0.25 |
| territorial emphasis | 0.30, 0.25, 0.45 |

## Boundary-profile schemes

Each value is repeated across the three criteria, producing three profiles that separate four classes.

| Scheme | Profile levels |
|---|---|
| inclusive | 0.40, 0.60, 0.75 |
| selective empirical standing | 0.50, 0.67, 0.80 |
| stringent | 0.60, 0.75, 0.90 |

## Indifference, preference and veto thresholds

The same threshold values are applied to all three percentile-normalized criteria within a configuration.

| Scheme | q | p | v |
|---|---:|---:|---:|
| narrow | 0.03 | 0.10 | 0.30 |
| baseline | 0.05 | 0.15 | 0.40 |
| wide | 0.08 | 0.20 | 0.50 |

The thresholds are expressed on the 0–1 percentile scale.

## Lambda values

The credibility cut levels are:

- 0.65;
- 0.70;
- 0.75.

## Baseline specification

The reference specification is:

- equal weights;
- selective empirical standing profiles;
- baseline thresholds;
- lambda = 0.70.

## Assignment procedure

The code uses a local implementation imported from `src/electre_tri_b_core.py` and calls:

```python
pessimistic_assignment(...)
```

The adopted procedure is therefore the classical pessimistic ELECTRE TRI-B assignment. A municipality is compared with the ordered boundary profiles, and assignment follows the pessimistic rule implemented in the local core.

## Ties and equal values

Input percentile ranks use `rank(method='average', pct=True)`. Municipalities tied on an original criterion therefore receive the same average percentile rank.

Threshold-based comparisons, equality at profile boundaries, credibility ties and assignment ties are handled by the comparison operators in `pessimistic_assignment`. Before public release, the local core should be preserved and its exact comparison operators should be described or tested explicitly. No alternative tie-breaking rule should be introduced without checking whether assignments change.

## Outputs

For each municipality, the implementation records:

- baseline class and label;
- minimum and maximum class across 108 configurations;
- median class;
- percentage assigned to High or Very high;
- percentage assigned to Very high;
- whether the class is stable across all configurations.

It also records convergence indicators involving:

- scenario-based priority;
- baseline ELECTRE priority;
- Pareto front membership.

These convergence indicators are descriptive triangulation. They do not constitute independent validation.

## Implementation status

The configuration is stored in `config/electre_tri_b_v25.json`. The analysis is implemented in `src/electre_tri_b_v25.py`, with the sorting core in `src/electre_tri_b_core.py`.

## Reproducibility note

The ELECTRE stage requires the consolidated municipal table and Pareto output produced by earlier stages. A clean run should verify that all 108 configurations are generated and that baseline and sensitivity outputs reproduce the manuscript tables exactly.
